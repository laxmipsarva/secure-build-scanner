## Repository

`build-scanner` — a static security scanner CLI, also packaged as the composite
GitHub Action `laxmipsarva/secure-build-scanner` (`action.yml`). It scans a local
source/build folder for SQL/NoSQL injection, GraphQL, CORS, CSP, CSRF, bot-handling,
user-agent, and API-vulnerability patterns. Pure static analysis: **no database, no
server, no external services, no env vars, no secrets.**

## Commands

Run from the repo root:

| Task | Command |
|---|---|
| Install | `npm ci` |
| Build | `npm run build` (outputs to `dist/`) |
| Typecheck | `npm run typecheck` |
| Tests (all) | `npm test` |
| Tests (watch) | `npm run test:watch` |
| Run CLI (dev) | `npm run dev -- <path> [flags]` |
| Run CLI (built) | `node dist/cli.js <path> [flags]` |
| List rules | `node dist/cli.js rules` |

CLI flags: `-f json`, `-r <ids>`, `--fail-on <severity>`, `-l`. With `--fail-on high`
the process exits `1` when a finding at/above that severity exists, `0` otherwise
(invalid value exits `2`); without `--fail-on` it always exits `0` after reporting.

There is no server to start and nothing to listen on — "local dev" is
install → build → run the CLI. No env vars are required.

## Notes / gotchas

- `dist/` is gitignored build output — run `npm run build` before `node dist/cli.js`.
- CI (`.github/workflows/test-action.yml`) runs the composite action against
  `tests/fixtures` with `format: json` on push/PR to `main`.
- Keep `action.yml` inputs in sync with CLI flags in `src/cli.ts` (the action
  shells out to `dist/cli.js`).
- `bun.lock` should never be committed; npm + `package-lock.json` is the manager.
